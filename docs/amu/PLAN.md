## 0. 結論

URL・アウトライン・段落の3機能は、いま**3つの同じ重さの一覧**として横に並んでいます。書く場所は上の大きな箱に1つあり、置いたものがどの列のどこへ入るかは、置いてから探すことになります。わかりにくさの正体は次の3つです。

1. **書く場所と、入る場所が離れている**: 上の書き口からアウトラインへ置くと、選んでいる行を無視して一番上に入ります。アウトラインの中で書く道もあり、入り方が2通りあります。
2. **順番と呼び名が場所ごとに違う**: 列はアウトライン・段落・参考URL、書き口の選択は参考URL・アウトライン・段落、コピーの文は参考URL・アウトライン・段落の順です。スマホでは、棚と書き口の選択が2段に並びます。
3. **3つがつながっていない**: アウトラインの行と段落、参考URLの間に関係を表す手段がありません。「段落に複製」は写しを作るだけです。スマホでは階層の字下げが消え、親子が見えません。

そこで、**3つを「並べた一覧」から「1つの書き物の、骨・肉・出典」へ組み直します**。書き口は1つのまま、いる場所へ運ばれてきます。アウトラインでは「次の一行」として行の間に入り、書きながらTabで組めます。一行は段落へ育ち、URLはアウトラインへ引用でき、清書では段落がアウトラインの行の下へ編み込まれます。データの形(IndexedDB・Supabase・バックアップ)は変えません。

| 段階 | 名前 | 一言 | 版 |
|---|---|---|---|
| P1 守 | 揃える | 順番・呼び名・既定・壊れを揃える。スマホの字下げを戻し、置いた先を知らせる | v0.7.2 |
| P2 破 | そこで書く | 上の箱をやめ、書き口が「いる場所」へ来る。PCは画面が動かず欄ごとに流れる | v0.8.0 |
| P3 離 | 編み上げる | 一行が段落に育ち、URLが引用になり、清書で一本の文書に編み上がる | v0.8.1 |

驚きは、書く行為の流れに沿って5つ置きます。

1. **開いたら、もう書ける**: 新しいメモは題を書いてEnterで、そのまま一行目へ移ります。PCではアウトラインの最後に「次の一行」がいつも見えています。
2. **書きながら組める**: Enterで次の行、Tabで字下げ、Shift+Tabで字上げ。スマホは書き口の左の「↰ ↳」で同じことができます。
3. **行き先が見える**: アウトラインの書き口にURLを書くと「→ 参考URLへ置きます」と出て、右の欄に「ここに入ります」が灯ります。どこで貼ってもURLは参考URLへ入り、題名があとから朱で届いて墨に乾きます。
4. **一行が段落へ育つ**: Shift+Enterを押すと、書き口が文を抱えたまま段落の欄へ移ります。行の「¶ 段落にする」を押すと、行の文が段落の見出しへ飛んで、続きを書き始められます。
5. **清書で編み上がる**: 清書にすると、行が紙の上へ収まり、結ばれた段落はアウトラインの行のすぐ下へ編み込まれます。

## 1. 依頼の読み方

- 「機能は踏襲しつつ、UIをゼロベースで」: 保存できるもの・できる操作は1つも減らしません(第5章の行き先表)。画面の構成・入口・順番・つながりは、今の形にとらわれずに考え直します。
- 「使い方を考えたときに、よりわかりやすい形」: 本人の使い方は「リサーチ→構造化→再リサーチ→プロンプト化」です(前回の計画の依頼)。URLを集め、アウトラインで組み、段落で書き下ろし、清書やChatGPTへ渡す流れを主筋にします。
- 「UXを最重視」: 迷わない・指の下で画面が動かない・キーボードを追いかけない・押せる大きさ(スマホ44px)を、見た目より先に満たします。
- 範囲: メモの編集画面(PC・スマホ)、清書、余白の入口です。メモ一覧とタグ管理は変えません。

### 2.4 既にある調べと外部の知見

- **P0実証(実験ブランチ `experiment/p0-inline-outliner-ux`、10/15〜16)**: 「行そのものを編集の中心に置く」べきで、ただし「分類しなくても書ける未整理の入口」は残すべき、という結論です。本番の置き換えは保留でした。今回はこの結論を本番の構造の中で実現し、未整理の入口は「どこで貼っても」と書き口の自動の行き先で残します。
- **アウトライナーの約束(Workflowy・Dynalist)**: Enterで同じ階層の次の行、Tab・Shift+Tabで階層、開いた親の行末でEnterを押すと最初の子になります。見えた場所に入るという約束です。
- **iOSのキーボード(Quick Linksの10/12の計画「揺らさずに、仕舞う」)**: 下に固定した入力欄をキーボードの動きに合わせてJSで追いかける形は、iOS 26の `visualViewport` の不具合に巻き込まれます。Quick Linksでは9/30と10/10の計画で直しきれず、10/12に「動く原因(キーボード)を呼ばない」方針へ切り替えました。今回のスマホの書き口は、画面の上半分(上から100px前後)の流れの中に置き、キーボードを追いかけません。
- **指の下で画面を動かさない**: 試作で、書き口から指を離した瞬間に添える道具の段が消え、一覧が詰まって押した場所がずれました。出し入れする部品は「書きかけがあるとき」だけ出し、置いた知らせは一覧に重ねて出します(押し下げない)。
- **View Transitions**: 同じ名前の要素どうしを、更新の前後でなめらかにつなげます。名前を付けた要素だけを動かし、画面全体の写しは動かさない設定にすれば、v0.7.1で消した残像は出ません。動きを減らす設定では使いません。
- **押せる大きさ**: WCAG 2.2の2.5.8(最小24×24px)を下限に、スマホは44pxにします。

## 4. 守破離の提案

### P1 守「揃える」:順番・呼び名・既定・壊れを揃える

構成は変えず、迷いの原因になっている「ずれ」を直します。

- **一つの順番**: どこでもアウトライン→段落→参考URLにします(清書の要点→本文→参考と同じ並び)。書き口の置き先と、コピー・.txt・ChatGPTに渡す文をこの順にそろえます。ショートカット(Ctrl+Shift+1/2/3)と列は、もともとこの順です。
- **スマホは構造が見える**: 字下げを戻し(1段16px)、完了した行は墨の淡色と打ち消し線にします(PCも同じ)。開いたときの棚はアウトラインにします。
- **見えた場所に入る**: 開いている親の下書きは「最初の子」に、それ以外は「次の兄弟」に入れます。欄の描かれる位置と結果を一致させます。
- **連れて行かない、でも知らせる**: スマホで別の棚へ置いても棚は移さず、「参考URLに置きました ― 参考URLを見る」を一覧の上に4秒重ねて出します。棚の数字が弾みます。
- **書き始めの道**: 新しいメモは、題を書いてEnterで書き口へ移ります(PC・スマホ)。題の「」の中から書き始める今の動きは残します。
- **案内を操作と一致**: 段落を書くときの案内は「段落を書く(Ctrl+Enterで置く)」にします。
- **帯を1行に(スマホ)**: 戻る・題・タグ・清書・メモの操作の1行にし、保存の状態は題の横の小さな点にします。余白は「メモの操作」から開きます(PCは今の帯のまま)。
- **項目の日時は既定で出さない**: 「項目の日時を表示」は残し、既定をオフにします(第11章 D3)。
- **隠れた置き換えを片付ける**: `vite.config.ts` のビルド時の置き換えをやめ、効いている1件(スマホのリンク欄でクリップボードを仮に入れる)をソースへ移します。効いていない `MobileNewMemoTitleFocus` を外し、新しいメモの道はReactの中で書きます。

### P2 破「そこで書く」:上の箱をやめ、書き口が「いる場所」へ来る

**書き口は1つのまま、置き場所(スロット)を3つ持ち、いる欄へ運ばれます**。いない欄には細い入口だけが残ります。

| 欄 | 書き口がいるとき | いないとき |
|---|---|---|
| アウトライン | 行の間の「次の一行」。字下げは入る深さに合わせる | 「＋ 次の一行を書く」 |
| 段落 | 見出し(任意)+本文。選んだ段落の後ろ、なければ末尾 | 「＋ 段落を書く」 |
| 参考URL | URL+備考(「＋ 備考」で開く)。一覧の先頭 | 「＋ URLを貼る」 |

- **アウトラインの「次の一行」**: 選んだ行のすぐ下へ来ます(開いた親なら最初の子、それ以外は次の兄弟)。Enterで置くと、次の一行が新しい行の下へ進みます。Tab・Shift+Tabで入る深さを変えます。空のまま↑を押すと上の行へ戻り、Escで離れます。最後の位置にいるときは、欄の下端に貼り付いていつも見えます。
- **行き先は形で決まる**: アウトラインの書き口にURLだけを書くと参考URLへ置き、「→ 参考URLへ置きます」を出します。Shift+Enterで改行すると、書き口が文を抱えたまま段落の欄へ移ります。複数行のURLを貼ると、まとめて参考URLへ置きます(今の動き)。
- **欄の移り方**: Ctrl+Shift+1/2/3で、書き口をアウトライン・段落・参考URLへ運びます。行を選ぶと、空の書き口はついてきます。書きかけの書き口は、その場に残ります。
- **どこで貼っても**: 入力欄の外で貼ると、URLは参考URLへ置き、ふつうの文は書き口へ入れます(置くのはEnterで)。
- **PCは画面が動かない**: 帯の下を3つの欄で埋め、欄ごとに流れます。v0.7.0の幅の比(42:38:20)と、921〜1199pxで参考URLをレールへ畳む動きは残します。
- **段落は文書の順**: 段落は手動の順を既定にし、触れると「上へ移す・下へ移す」が出ます。タグでまとめる・並び順は、今までどおり選べます(第11章 D2)。
- **行の道具は3つまで**: 触れたとき(ホバー・フォーカス・選択)だけ出します。アウトラインは「¶ 段落にする(P3)・⌕ この枝に集中・⋯ 項目の詳細」、段落は「上へ移す・下へ移す・⋯」、参考URLは「アウトラインに引く(P3)・URLを編集・⋯」です。書いてある気持ち・タグ・リンクは、今までどおり行に見せます。
- **項目の詳細にまとめる**: 完了・段落に複製(P3で「段落にする」に置き換え)・集中・気持ち・リンク・タグ・評価・動かす4つ(上げる・下げる・上へ・下へ)・コピー・新しいメモにする・段落へ移動・削除を1つの小窓に集めます。PCは行のそばに、スマホは下からのシートで出し、「動かす」を一番上に置きます(2タップで字下げ)。スマホで気持ち・リンク・タグを書くときは、画面の上半分のカードで書きます。
- **スマホの書き口**: 棚がそのまま行き先です(置き先の3択は消します)。アウトラインの棚では左に「↰ 字上げ・↳ 字下げ」があり、一覧には「↳ ここに入ります」が灯ります。添える道具(気持ち・リンク・タグ)は書きかけがあるときだけ2段目に出します。
- **アウトラインの上の帯と下の帯をなくす**: 「Enter 編集・Tab 階層…」の案内は、書き口の案内とショートカットの説明へ移します。高密度の切り替えは列のメニューへ、「直前の移動を戻す」は動かした直後の知らせ(戻す)へ移します。

### P3 離「編み上げる」:一行が段落に育ち、URLが引用になり、清書で一本になる

- **段落にする**: 行の「¶」で、その行の文を見出しにした段落の書き口が段落の欄に開きます。行の文が見出しへ飛ぶ移り変わりで、つながりを見せます。結ばれた段落がすでにあれば「段落を開く」になり、その段落へ移ります。今の「段落に複製」は、この操作に置き換えます(「段落へ移動」は詳細に残します)。
- **結び目(データは変えない)**: 段落の見出しが、アウトラインの1行と同じ文なら結ばれているとみなします。同じ文の行が2つ以上あるときは結びません。結ばれた行には「¶」、段落には「↖ 2.2」(行の番号)の印が付き、押すと相手へ移って両方が朱の淡色で灯ります。結ばれた行の文を直すと、段落の見出しも同じ文に直します(第11章 D5)。
- **アウトラインに引く**: 参考URLの「↖」で、題名をアウトラインの次の一行に入れ、リンクを付けます。URLの側には「引用 1」が付きます。
- **行き先の予告**: アウトラインの書き口にURLを書いている間、参考URLの欄の入口に「ここに入ります(題名はあとから届きます)」を灯します。
- **清書で編み上がる**: 結ばれた段落は、要点の行のすぐ後に編み込みます。本文には、結ばれていない段落だけを並べます。清書へ切り替えると、行が紙の上へ収まる移り変わりを使います(先頭60件まで。動きを減らす設定では使いません)。

## 6. 画面の型

- **PC(1366×633)**: 帯52px。その下を3つの欄(42:38:20、間32px)で埋め、ページは動きません。欄の見出しは40pxで、下に墨の罫を1本引きます(v0.6.1の型)。行は32px(高密度28px)、字下げ1段20px、本文15pxです。
- **中間(921〜1199px)**: 参考URLは44pxのレールに畳みます(今と同じ)。Ctrl+Shift+3と、どこで貼っても、で開かずに使えます。
- **スマホ(〜920px)**: 帯48px(1行)→棚40px→書き口(1行。書きかけがあると添える道具の段が出る)→一覧です。最初の行は上から150px前後に来ます。行は44px、字下げ1段16px、本文16px(iOSの自動拡大を避ける)です。
- **色と動き**: v0.6.1の型(紙・墨・朱、余白、文字、角丸、影、120・200・320ms)をそのまま使います。新しい色は足しません。朱は「いま・ここ」(選んだ行・灯った置く・置いたばかりの字・行き先の予告・結び目の灯り)にだけ使います。

## 8. 選ばなかった案

- **すべてを1つのアウトラインに統合する(段落もURLも行の一種にする)**: データの移し替えが要り、P0実証でも「独立した段落やURLの高速収集」を失うとして退けられています。
- **段落をアウトラインの子として保存する**: 親の種類の制約とクラウドの外部キーにかかります。関連付けの表を足す案(P0の `entry_links`)は、同期と削除の設計が先に要ります。見出しの一致で、データを変えずに結べます。
- **見出しの一致を「似た文」まで広げる**: 結び目が勝手に増えます。完全に同じ文だけにします。
- **入力欄の外でキーを打つだけで書き始める**: 日本語入力では最初の1字が欠けるか、ローマ字のまま入ります。貼るときだけ「どこでも」にします。
- **スマホで行を左右に払って字下げする**: iOSの戻る操作や縦の送りとぶつかり、見つけにくい操作です。詳細の「動かす」(2タップ)と書き口の「↰ ↳」にします。
- **書いている欄を自動で広げる(列の幅を動かす)**: 押そうとした部品が動きます。幅は固定し、参考URLの題は2行まで見せます。
- **清書で段落を見出し(h3)にして章立てにする**: 見出しの段差が増え、短いメモでは大げさです。行の下に一字下げで入れます。

## 9. 危険と対策

| 危険 | 対策 |
|---|---|
| 書き口を運ぶと、フォーカスが消える・打った字が消える | 運ぶ直前にフォーカスと選択位置を覚え、運んだ直後に戻す。変換中は運ばない。受け入れ確認P2-4〜P2-10で続けて打つ |
| 下書きの保護が外れる | 書き口の部品は1つのまま作り直さず、同じ下書きIDを使う。前回のP2-13(下書きを拾う)を流し続ける |
| 旧台本(仕立て・研ぎ・アウトライン・13幅)が、消した3択を探して落ちる | 3択の操作をCtrl+Shift+数字と棚へ置き換える(依頼書の付録B)。項目を消して緑にしない |
| 既定の変更(並び順・タグでまとめる・日時)が利用者の好みを消す | 既定以外を選んでいた値は引き継ぐ。変えた既定はリリースノートに書く |
| 見出しの書き換え(結び目)が意図しない段落を変える | 同じ文の行が1つだけのとき、同じメモの中の、見出しが完全に同じ段落だけ。受け入れ確認P3-3 |
| 移り変わりで残像やタップの奪い合いが戻る | 名前付きの要素だけを動かし、全体の写しは止めたまま。`::view-transition` は押せないまま |
| PCで欄ごとに流れると、印刷や清書が切れる | 清書は今までどおりページで流す。印刷は紙だけ(前回のP3-6を流す) |
| 中間の幅で参考URLの書き口が見えない | 畳んだレールのまま、Ctrl+Shift+3でレールを開いて書き口を出す。どこで貼っても入る |

## 11. 人が決めること

- **今**: 試作を触って、方向を決めてください。特に次の5点です。推奨のまま進める場合は、何もしなくてかまいません。
  - **D1 コピーの文の順**: メモをコピー・.txt・ChatGPTへ渡す文を、アウトライン→段落→参考URLの順にします(推奨)。今の順(参考URLが先頭)を残す案もあります。
  - **D2 段落の既定**: 段落は手動の順・タグでまとめないを既定にします(推奨)。並び順とタグでまとめるは、今までどおり選べます。
  - **D3 項目の日時**: 既定で出さず、詳細と「項目の日時を表示」で見られるようにします(推奨)。
  - **D4 スマホで置いたとき**: 棚は移さず、置いた先を4秒知らせます(推奨。前回の受け入れ確認P2-12「置いた棚のタブへ移る」を置き換えます)。
  - **D5 結び目の見出し**: 結ばれた行の文を直したとき、段落の見出しも直します(推奨)。直さない案では、結び目がその場で外れます。
