## 0. 結論

kakidasの「惜しさ」は、方向ではなく仕上げの3点から来ています。

1. **色の役割の取り違え**: v0.6.0で957色を13のトークンへ寄せた際、白い面135か所が罫線の色に、中立の線95か所が朱に置き換わりました。白の半透明は墨の半透明になり、一覧のカードが濃い灰色で読めません。
2. **余白と文字に体系がない**: CSSの余白の値は56種、文字の大きさは35種、太さは18種です。行の左右の余白が0で、字が面の端に接しています。PCでは本文の左端が5つの位置に散っています。
3. **線と箱の重ね過ぎ**: PCの最初の画面に枠線が60辺あり、うち26辺が朱、16辺が破線です。帯・書き口・列・行・ボタンがそれぞれ囲まれています。

加えて、見えにくい不具合が1つあります。**文を置くたびに、画面の描画が約4秒止まります**。打った字は入りますが、その間は見えません(ヘッドレスのChromiumで毎回再現。仕組み上、実機でも起きる見込みが高い)。

そこで、構造(書き口ひとつ・清書)はそのままに、3段階で研ぎます。

| 段階 | 名前 | 一言 |
|---|---|---|
| P1 守 | 戻す | 壊れて見える所を直す。色の役割を元の色から引き直し、読める・止まらないを取り戻す |
| P2 破 | 囲わない | 線と箱をやめ、余白と一本の背骨で並べる。線は構造に1本だけ |
| P3 離 | 研ぎ澄ます | 紙・墨・朱の手応え。置いた字が朱から墨へ乾き、清書に落款が押される |

驚きは、書く行為に沿って置きます。**書き口に触れると罫の上を墨の線が走り、書くと「置く」に朱が灯り、置いた字は朱から墨へ乾きます。清書には、紙に押し込まれた落款がかすれて残ります**。どれも1秒前後の小さな動きで、動きを減らす設定では出しません。データ(IndexedDB・Supabase)の形は変えません。

## 1. 依頼の読み方

- 「機能は悪くない」「方向性は悪くない」: v0.6.0の書き口ひとつ・余白・清書の構造と、紙・墨・朱の方向は保ちます。
- 「余白、枠線、細部、質感」: 色の役割、余白の刻み、文字の段、線と箱、影、状態の見せ方、動きを対象にします。
- 「UXを最重視」: 見た目より先に、読める(コントラスト比4.5以上・12px以上)、押せる(スマホ44px)、本文を隠さない、止まらない、を満たします。
- 範囲: 書く画面(PC・スマホ)、余白、清書、一覧と、そこから開くメニュー・シートです。タグ管理と各ダイアログは、色の役割の引き直しと型(トークン)の適用だけにします。

### 2.3 コードの所見

- CSSは20ファイル・12,629行です。`.entry-item` の規則は8ファイルに189個あります。上書きを重ねた結果、詳細度の競り合いと `!important`(42か所)が残っています。
- `styles-mobile-word-compact.css`・`styles-mobile-word-single-row.css`・`styles-cloud-upload-header.css` の3本は、v0.6.0で読み込みが外れ、使われていません。
- `src/lib/viewTransition.ts` の `waitForCreatedEntry` は、移り変わり(View Transition)の更新の中で `requestAnimationFrame` を待ちます。更新の間は描画が止まるため、新しい行がまだ無いとrAFが来ず、ブラウザーの上限の4秒まで止まります。本番のJSの写しで、待ちを `setTimeout` に替えると4,031msが82msになりました。
- 同じ理由で、置いた行に付ける印(`entry-item--fresh`)が、1つ前の行に付くことがあります。
- `vite.config.ts` の `applyKakidasUiConsistency` は、ビルド時に `EntryItem.tsx`・`EntryComposer.tsx`・`MemoEditorPage.tsx`・`MobileParagraphEditorSheet.tsx`・`types/memo.ts` の文字列を置き換えます。対象の文字列を変えると、置き換えが黙って外れます。
- スマホの「この項目の操作」の3つのボタン(気持ち・リンク・タグ)には、クラスもアイコンもありません。ブラウザー既定の灰色のボタンで表示されています。
- 余白の「Alt＋Q で開閉」は `::after` の文字で、スマホでも出ています。前回の確認は `innerText` を見ていたため見逃しました。

### 2.4 外部の知見と前提

- **カスケードレイヤー(`@layer`)**: 層の順が詳細度より先に効きます。Chrome 99・Safari 15.4・Firefox 97以降で使えます。既存のCSSを `@layer legacy` に入れ、新しい層を後ろに置けば、詳細度を競わずに上書きできます。ただし、前の層の `!important` は後の層の通常の宣言に勝ちます。
- **Vite 8の `@import … layer()`**: 手元でVite 8.0.16のビルドを試し、`@layer legacy{…}` として順番どおりに組まれることを確かめました。
- **和文の組み**: 本文は行送り1.6〜1.85、字間は0.02em前後、小さな注記は0.04〜0.06emにします。太さは端末の書体に合わせ、400と600の2つにします(BIZ UDPゴシックは400・700、ヒラギノ角ゴはW3・W6のため、650〜820は端末ごとに見え方が変わります)。
- **コントラスト**: 今の墨の3段(`#8e8a81`)は机の色の上で3.1:1です。日時や件数がWCAGの4.5:1に届きません。`#6c675f` にすると5.0:1になります。
- **押せる大きさ**: WCAG 2.2の最小(2.5.8)は24×24pxです。PCの行の道具は24px、スマホの操作は44pxにします。
- **画面の止まり**: View Transitionの更新の間は描画が止まり、`requestAnimationFrame` も来ません。更新の中で描画を待つ処理は、タイマーかMutationObserverで待ちます。

## 4. 守破離の提案

### P1 守「戻す」:壊れて見えるところを直し、読める・止まらないを取り戻す

レイアウトは変えず、土台を直します。

- **止まらない**: `waitForCreatedEntry` の待ちを `requestAnimationFrame` から `setTimeout(16)` へ替えます。上限300msはそのままです。新しい行の印は、移り変わりの更新の中で付けます(飛んで収まる間も「濡れた朱」が写り、着地後のちらつきが出ません)。外すのは「墨が乾く」の長さに合わせて1,800ms後です。
- **層に分ける**: `src/styles-index.css` を作り、既存の18本を `@layer legacy` で読み込みます。新しい見た目は `src/styles-togu.css`(`@layer togu`)にだけ書きます。`main.tsx` は `styles-index.css` だけを読み込みます。
- **色の役割を引き直す**: `node docs/togu/remap-colors.mjs --write` で470行を直します。
- **片付け**: 使われていない3本のCSSを消します。一覧のカードの抜粋とタグに付いた `!important` 12行を外します(新しい層で文字の大きさを決めるため)。
- **型**: 墨の3段を `#6c675f` にし、余白・文字・角丸・影・動きの型を足します(第5章)。
- **仕上がっていない部品**: スマホの操作シートを一列の目録にそろえ、3つのボタンに線画アイコンを付けます。落款を2字の縦組みで枠に収めます。余白の呼び名を「余白」へそろえ(「余白を消す」「余白を閉じる」)、スマホではAlt+Qを出しません。一覧の検索欄は「題・本文・タグで探す」にして、スマホでも切れないようにします。

### P2 破「囲わない」:線と箱をやめ、余白と一本の背骨で並べる

- **一本の背骨**: ページの左右32px+紙の内側12px=44pxに、題・書き口・列見出し・行の本文をそろえます。「戻る」は線画の「‹」にして、左の余白へぶら下げます。スマホは画面の端から16pxにそろえます。
- **帯**: 下線と枠をやめます。清書は小さな印の付いた朱の字、余白とメモの操作は静かな文字とアイコンにします。メモのタグは黒い札をやめ、墨の字にします。
- **書き口**: 枠を外し、紙の面と淡い影だけで浮かせます。2段にまとめます(書く欄と置く/置き先と気持ち・リンク・タグ)。高さは120pxから100pxになります。置き先は溝の中の切り替え、気持ち・リンク・タグは破線をやめて文字とアイコンにします。
- **列**: 縦線をやめ、列の間を32pxの余白にします。見出しの下にだけ墨の罫を1本引きます(帳面の見出しの罫)。件数は見出しの隣へ寄せます。
- **行**: 罫線の色の塊をやめ、机の上に罫だけを引きます。左右に12pxの余白をとり、触れると紙が持ち上がるように白くなります。日時と件数は12px・墨の3段です。
- **行の道具(PC)**: 1行目の字を隠すグラデーションをやめ、日時の行の右に出します。満足度は星と数、ほかは24pxの線画アイコンです。
- **段落・参考URL**: 段落の番号の枠と縦棒をやめ、見出しの前の小さな数字にします。参考URLは頭に印の列をとり、題・ドメイン・日時を一本の線にそろえます。
- **タグのまとまり・完了**: 枠と濃い帯をやめ、見出しの行と罫だけにします。開閉の「⌃⌄」は線で描いた山形にして、回して見せます。
- **メニュー・シート**: 印(✓)の有無にかかわらず項目名の左端をそろえます。消す操作は赤にして、罫で分けます。
- **余白**: PCではページの右に開く便箋にし、ぼかしと暗転をやめて、メモを見ながら書けるようにします。罫は入力欄にだけ引き、字は罫の上に乗ります。

### P3 離「研ぎ澄ます」:紙・墨・朱の手応え

- **紙の目**: 机にだけ、目に見えるか見えないかの紙の目を敷きます(SVGのノイズ、強制配色と印刷では消す)。書き口と清書の紙は平らなままにします。
- **墨の線が走る**: 書き口の罫は、触れると左から墨の線が走ります。枠で囲む代わりに、線を引いて「いまここに書く」を示します。
- **朱が灯る**: 「置く」は書くまで沈んだ文字で、書くと朱の地が灯ります。
- **墨が乾く**: 置いた字は朱で現れ、1.6秒かけて墨に乾きます。行の地も朱の淡色から机の色へ戻ります。前の印(左の朱の縦線)は外します。
- **保存も乾く**: 保存中は「保存中…」が朱、保存済みで墨の淡色へゆっくり戻ります(`data-state` で切り替え)。
- **押した落款**: 清書の落款は2.5pxの朱の枠に2字を縦に組み、少し傾けます。SVGのノイズでかすれを出し、紙に重ねて(乗算)押し込みます。開くと軽く押される動きが付きます。
- **版面**: 清書の要点はぶら下げ(2行目が字の頭にそろう)、本文は一字下げ、見出しの横に細い罫を引きます。

## 7. 選ばなかった案

- **CSSを一から書き直して一本化する**: 12,629行の置き換えは、壊すものが多すぎます。今回は層で上書きし、旧CSSの整理は次の段にします。
- **行をカードに戻す・列に枠を付ける**: 箱が増えます。罫と余白で足ります。
- **罫をすべて消す**: 行の境目が分からなくなります。行の間の罫と、列見出しの罫は残します。
- **気持ちのラベルを「—」に置き換える**: 見た目は締まりますが、何の行か分かりにくくなります。小さな墨の淡色で残します。
- **紙の目を書き口と清書にも敷く**: 字の読みやすさが下がります。机だけにします。
- **ウェブフォントを読み込む**: 速さとオフラインを優先し、端末の書体のままにします。
- **ダークモード**: 依頼の外です。型(トークン)にしてあるので、後から足せます。
- **満足度を星5つの部品に作り直す**: 機能の変更になります。今の選択(`select`)を星と数で見せるだけにします。

| 層に入れたことで、旧CSSの見た目が変わる | 層の中の順番は今の読み込み順と同じです。試作は同じ組み方で30/30と前回の29/29を確認済みです |
| 色の引き直しで、意図した色まで変わる | 取り違えと分かる組み合わせ(面・線・文字・影ごと)だけを直します。470行の差分をPRに載せ、PCとスマホの撮影で確かめます |
| `!important` を外したことで、一覧の別の表示が崩れる | 外すのはカードの抜粋とタグの12行だけです。一覧の撮影と受け入れ確認(P1-5・P2-12)で確かめます |
| `vite.config.ts` の置き換えが外れる | 置き換え対象の文字列(依頼書の付録)を変えません |
| `styles-tokens.css` を読めない環境がある | 読み込みの順番に名前を書くだけで、中身は触りません。新しい値は `styles-togu.css` で上書きします |
| 4秒の止まりを直すと、置く動きが崩れる | 待ちの上限は同じ300msです。前回のP3-7(移り変わり)と今回のP1-1・P1-2で確かめます |
| 紙の目やかすれが重い | 160pxと64pxの小さなSVGを並べるだけです。強制配色・印刷では消します |
