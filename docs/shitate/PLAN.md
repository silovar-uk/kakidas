# kakidas 守破離計画「飾らずに、仕立てる」

- 作成: 2026-10-09(Opus 5.5)。計画・試作・受け入れ確認まで作成済みで、アプリのコードは未変更です。
- 基準: `main` の `fad9299`(v0.5.76、PR #10「段落の自動省略と3列折り畳み」まで)
- 本番: https://kakidas-3gqw.vercel.app/(Vercelの `kakidas-3gqw`。`main` へのマージで自動デプロイ)
- 試作: `docs/shitate/mock.html`(非公開Artifact https://claude.ai/artifact/QKgvnfcwAKqrY3bkS6WAZ5)
- 受け入れ確認: `docs/shitate/qa.mjs`(29項目。試作では、アプリにしかない下書きの1項目を除く28/28が合格。本番の現状は `baseline-2026-10-09.txt`)
- 実装依頼: `docs/shitate/HANDOFF-sonnet.md`

## 0. 結論

kakidasのやぼったさは、配色や角丸の好みではなく、**書く前と書いた後の操作が、書いている最中にも全部見えていること**から来ています。PCの最初の画面には操作部品が70個、色が70色並び、スマホでは最初の項目が画面の607px下まで出てきません。さらに保存中は入力欄が止まり、続けて打つと字が消えます。

そこで3段階で仕立て直します。

| 段階 | 名前 | 一言 |
|---|---|---|
| P1 守 | 飾らない | 入力を止めない。操作は触れたときだけ。色・書体・アイコンを一つの体系にする |
| P2 破 | 迷わない | 3つの入力欄を「書き口」ひとつにし、書いた形で置き先を決める。上の帯と列見出しの操作をメニューへ |
| P3 離 | 仕立てる | ひと押しで、作業台のメモが要点・本文・参考の組まれた一枚の「清書」へ移り変わる。朱の落款を押す |

驚きは2つに絞ります。**書きながら器が育つ書き口**(改行すると文が段落へ育つ)と、**散らかった作業台が一枚の紙に組み上がる清書**です。データ(IndexedDB・Supabase)の形は変えません。各段階は単独でも価値が出るように分けてあり、P1だけで止めても使い心地は良くなります。

## 1. 依頼の読み方

- 「メモ部分」は、メモを開いて書く編集画面(`/memos/:id`)と読みました。黄色い付箋の「一時メモ」も含めます。
- 「全体のUI」は、色・書体・アイコンの体系を一覧(`/`)とタグ管理(`/tags`)にも通す範囲とします。一覧は10/6に「静かなタグ構造UI」へ作り直したばかりなので、構造は変えません。
- 「驚き」と「誇らしさ」は、毎日の操作の滑らかさ(守・破)と、メモが成果物に化ける瞬間(離)で出します。

### 2.2 コードの所見

- 編集画面の主な部品は `MemoEditorPage.tsx`(1206行)・`EntryColumn.tsx`(1306行)・`EntryItem.tsx`(1149行)・`EntryComposer.tsx`(1086行)です。
- **9個の部品が、画面の外からクラス名で要素を探し、ボタンを差し込んだり並べ替えたりしています**(`MutationObserver`・`createPortal`・`insertBefore`)。上の帯に「クラウド保存」「クラウドに合わせる」「ショートカット」が後から並び、帯が積み上がって見える根本原因です。一覧は依頼書の付録Aにあります。
- CSSは `styles.css`(8177行)の上に19本の上書きファイルが重なっています。文字サイズは21種、角丸は18種で、体系がありません。
- 入力欄は、保存中(`isSubmitting`)と、メモ全体で書き込みが残っている間(`isSaving` = `pendingWrites > 0`)に `disabled` になります。`disabled` の欄は打鍵を受け取らないため、Enterの直後に打った字が消えます。
- 参考URL列は、単語列(`kind: "word"`)をURLの受け皿に作り直したものです(10/6)。データの種別名は `word` のままです。
- 項目の作成(`memoRepository.createEntry`)は、並び順の計算と書き込みを同じトランザクションで行います。続けて送っても順番は崩れません。一方、作成時のIDは常にリポジトリ側で振られ、外から渡せません。
- ルートの `app.js`・`diff-core.js`・`styles.css`・`tests/` は別アプリ(Text Review Studio)の残りで、kakidasのビルドに含まれません。今回は触りません。

### 2.3 外部の知見

- **段階的開示**: 補助操作は必要になったときに出すのが定石です。ただしホバーだけに隠すと見つけにくく、タッチでは使えません。キーボードのフォーカスでも出し、タッチ端末には別の入口を用意します。
- **書く道具の定石**: Drafts・Bear・Thingsは、書き始めの摩擦を消し、行き先や整理は後で決めます。Draftsの「まず書いて、行き先は後で選ぶ」は、書き口ひとつの根拠です。
- **View Transitions**(同一文書)は、Safari 18・Chrome 111・Firefox 133以降で使えます。Reactの `<ViewTransition>` はCanary版だけなので、`document.startViewTransition` と `flushSync` を直接使います。
- **iOS Safariのキーボード**: `interactive-widget` に未対応で、下端に固定した入力欄はキーボード表示で位置が安定しません。
- **和文の組版**: `text-autospace` はChrome 140・Safari 18.4以降で、和文と英数字の間に字間を入れます(文字は増えません)。`palt` は入力欄に当てるとBlinkで括弧が重なる報告があるため、題と見出しだけに使います。
- **Windowsの書体**: 游ゴシックはWindowsの既定がRegularで細く見えます。BIZ UDPゴシックはWindows 10(1809)以降に同梱です。この端末にはNoto Sans JP/Serif JPも入っています。
- **`field-sizing: content`** はSafari 26.2以降で、iOS 18では効きません。今の自動伸長の処理を残します。
- **書式つきコピー**: Safariは `ClipboardItem` の `text/html` に対応しますが、非同期処理をまたぐと拒否されます。清書のコピーは、描画済みの紙を選択して同期的にコピーします(既存の `copyToClipboard` と同じ考え方)。

## 4. 守破離の提案

### P1 守「飾らない」:型は変えず、摩擦と雑音を取る

- **入力を止めない**: 送信の瞬間に値を取り出して入力欄を空にし、保存は後ろで進めます。失敗したら書いた字を入力欄へ戻します。
- **行の操作は触れたときだけ(PC)**: 満足度・完了・気持ち・リンク・タグ・その他をひとまとまりにし、ホバーかキーボードのフォーカスで現れるようにします。入力済みの気持ち・タグ・リンクと満足度の地の色は常に見えます。
- **スマホの行は「⋯」ひとつ**: 満足度(0〜5)・完了・気持ち・リンク・タグを、今の操作シートへ集めます。
- **色・書体・アイコンを一つの体系へ**: 13色のトークン、文字6段、角丸3種、影2種、名前付きのz-index。和文を先頭にした書体、題と見出しに `palt`、本文に `text-autospace`。記号の文字を線画アイコンへ置き換えます。
- **スマホでキー表示を出さない**: 一時メモの「Alt+Q」など。

保持する仕様: 満足度を本文やコピーに混ぜない、気持ち・備考が空なら余白を作らない、タグ見出しの「#タグ ＋」、段落の自動省略(PR #10)、列の折りたたみ(PR #9)。

書き換える原則(HANDOVER.mdも直す): 「PCでは気持ちのペンとリンクを完了の右側へまとめる」は「ひとまとまりにして、触れたときに出す」へ。スマホ単語の「3列×2段の操作面」は、参考URL化で前提が変わったため外します。

### P2 破「迷わない」:書く場所をひとつ、操作の置き場を二つに

- **書き口**: PCは題の下、スマホは棚のタブの下に入力欄をひとつ置きます。置き先は「参考URL・文・段落」です。
  - URLだけを書けば参考URL。改行が入るか、段落タイトルを書けば段落。それ以外は文(スマホは開いている棚)。
  - 文はEnterで置きます。Shift+Enterで改行すると段落へ育ち、段落タイトルの欄が開きます。段落ではEnterが改行で、Ctrl+EnterかShift+Enterで置きます(今の段落と同じ)。
  - 置き先は押して選び直せます(Alt+1/2/3も)。選び直した後は、置くまで自動で変えません。
  - 気持ち・リンク・タグは、今と同じ補助入力を書き口の下から開きます。
  - スマホで置くと、置いた棚のタブへ移ります。
  - タグ見出しの「#タグ ＋」の入力は今のまま残します。タグを固定して書き足す入口で、役割が違うためです。
- **上の帯を一本に**: 戻る・題(とメモのタグ)・保存状態・清書・余白・「メモの操作」だけにします。クラウドに保存/合わせる・ChatGPT・コピー・.txt・並び順・表示設定・ショートカット・完了の一括削除・メモの削除は「メモの操作」へ入れます。「ローカルのみ」は通常の状態なので出さず、クラウドの方が新しい・競合・失敗のときだけ「メモの操作」に点で知らせます。
- **列見出しを静かに**: 見出し・件数・畳む・「…の操作」だけにします。タグでまとめる・順番固定・コピー・すべて削除はメニューへ入れます。
- **余白(旧・一時メモ)**: 帯のボタンから開く右の引き出しにします(スマホは下からのシート)。黄色の付箋をやめ、紙の色に薄い罫線を引きます。保存先と内容はそのままです。
- **後付けの撤去**: 帯へ差し込む部品(`CloudUploadHeaderButton`・`ChatGptMemoButton`・`KeyboardShortcuts` の帯部分・`TemporaryMemoShortcut`)をメニューの項目やイベントに作り直し、`MutationObserver` を外します。

驚き: 書きながら器が育つ(文の欄が段落の欄へ変わる)。URLを貼った瞬間にサイト名と備考欄が出る。

### P3 離「仕立てる」:メモを成果物にする

- **清書**: 帯の「清書」で `?view=seisho` に移ります。題は「M/D 曜「…」」の中身を明朝で大きく出し、日付とメモのタグは日付行へ回します。文は「要点」、段落は「本文」(段落タイトルは小見出し)、参考URLは「参考」(サイト名と備考)として組みます。完了・満足度・文と段落の気持ちは入れません(「コピーに完了を含める」の設定には従います)。
- **移り変わり**: 題と各項目が、作業台の位置から紙の位置へ動きます(View Transitions)。戻るときは逆に動きます。動きを減らす設定では切り替えだけにします。
- **落款**: 紙の右下に朱の「書出」の印を押します。清書を開くと軽く押される動きが付きます。
- **書式つきでコピー**: Google DocsやNotionに見出しつきで貼れます。**印刷・PDF**: 紙だけを印刷します。
- **置く手応え**: 置いた文が、書き口から棚の位置へ飛んで収まります(同じ仕組み)。

## 5. 再リサーチで確かめたことと決定

| 設計を左右した仮定 | 確かめた結果 | 決定 |
|---|---|---|
| スマホの書き口を画面下(親指の位置)に固定できる | iOS Safariは `interactive-widget` 未対応 | 固定しない。タブの下に置き、上端を121pxまで上げる |
| ReactのView Transitionを使える | `<ViewTransition>` はCanary限定 | `document.startViewTransition` + `flushSync` を小さな関数に包む |
| 新しい項目の行へ飛ばせる | 作成は非同期で、IDはリポジトリが振る | `createEntry` に任意の `id` を通し、書き口で先にIDを作る。行が出るのを最大300ms待って打ち切る |
| 移り変わりの中で入力欄を空にしてよい | 試作で、続けて打った字が前の文とつながった | 送信の瞬間に同期で空にし、動きは「写し」の要素で見せる |
| 書式つきコピーは `ClipboardItem` で書ける | Safariは非同期をまたぐと拒否 | 描画済みの紙を選択して同期コピー。失敗したら今の文字コピー |
| `field-sizing` で自動伸長を置き換えられる | Safari 26.2以降のみ | 今のJSの自動伸長を残す |
| 和文の書体を先頭にしても崩れない | BIZ UDPゴシックはWindows 10(1809)以降に同梱 | ヒラギノ角ゴ→Noto Sans JP→BIZ UDPゴシック→游ゴシックUI→メイリオ |
| `palt` を全体に当てられる | 入力欄で括弧が重なる報告がある | 題と見出しだけ |

## 6. 選ばなかった案

- **文字数で段落へ自動で切り替える**: 打っている途中で置き先が揺れます。改行だけを合図にします。
- **本文中の「#タグ」をタグにする**: 本文の字を勝手に消すことになります。今のタグ入力を残します。
- **ダークモード**: 依頼の外です。トークンにしておけば後から足せます。
- **触覚フィードバック(iOSのswitch付きcheckbox)**: 非標準の抜け道です。驚きは清書に集めます。
- **一覧の作り直し**: 10/6に作り直したばかりです。体系の適用だけにします。
- **複数の文を束ねて段落にする**: データ操作が増えます。次の候補として残します。

## 7. 危険と対策

| 危険 | 対策 |
|---|---|
| 下書きの移行で書きかけを失う | 書き口が空のときだけ、古い段落・参考URLの下書きを拾います。拾ったら同じトランザクションで古い方を消します。書き口に字があれば古い下書きは残し、書き口の下に「前の下書き」を出します |
| 送信後に古い下書きの削除が新しい書きかけを消す | 作成とDraft削除は同じトランザクションです。作成の完了後、入力欄に続きがあれば下書きを保存し直します |
| 後付け部品を外して機能が消える | 付録Aの表どおりに1つずつ外し、外す前と後で該当の操作を手で確かめます |
| 色の一括置換で意味の色(危険・満足度)が潰れる | 置換表を依頼書に固定し、危険の赤と満足度の地色は別トークンにします |
| 移り変わりで画面が止まる | 置くときの待ちは最大300msで打ち切ります。名前を付ける項目は60件までにします |
| 入力を止めないことで二重に送る | 送信時に値を空にするので、同じ字は二度送られません |
